# Phase 7 audit operations

The Audit Query Service consumes the versioned CDEP Kafka domain topics into a tenant-partitioned, append-only PostgreSQL authority. Each tenant has one canonical SHA-256 hash chain ordered by ingestion time and stable record ID. Event time remains separately searchable; out-of-order events are retained and marked as late arrivals.

## Authority and recovery

- PostgreSQL table `audit_records` is authoritative. A database trigger rejects updates and deletes.
- Kafka topic, partition, and offset are unique. Event ID is also unique, so restart and replay are idempotent.
- Checkpoint advancement and record append share one serializable transaction.
- Invalid JSON, schema-incompatible events, and events without tenant context are represented in `quarantined_events` by safe error code and payload hash only.
- The current projection is never deleted by an operation. Replay, rebuild, and reconciliation jobs verify the existing authority and record their result before any future switching implementation is introduced.

## Reports and exports

Approved, versioned report definitions are server-owned. Runs capture the requester, tenant, parameters, snapshot boundary, row count, checksum, classification, state, expiry, and object-storage reference. CSV generation uses deterministic columns and neutralizes spreadsheet formulas. Artifact keys and filenames are generated by the server. The browser receives only a short-lived authorized S3 download grant.

Local Docker stores artifacts in Garage bucket `cdep-audit-artifacts`. Production must use private object storage, workload identity, and an externally correct signing endpoint.

## Health and diagnosis

- `/health/live`: process liveness.
- `/health/startup`: projection schema startup.
- `/health/ready`: PostgreSQL, Kafka consumer, and artifact-bucket readiness. It
  returns HTTP 503 while Kafka is disconnected so the Gateway and Kubernetes
  readiness checks fail closed.
- `/api/v1/audit/operations`: checkpoints, projection freshness, open quarantine count, and immutable job history.
- `/api/v1/audit/chain/verify`: bounded canonical chain verification.

Never copy Kafka payloads, signed artifact URLs, bearer tokens, database credentials, or raw evidence contents into logs or support tickets.

## Production configuration

Required secret/configuration values are `DATABASE_URL`,
`CURSOR_SIGNING_SECRET`, Kafka brokers and security credentials, and private
object-storage credentials.

The GKE deployment creates the `cdep_audit` AlloyDB database URL in
`cdep-database-urls` and stores the independent cursor-signing key in
`cdep-audit-secrets`. The `audit-migrate` Job must complete before the
`audit-query-service` Deployment becomes available. Preserve and back up
`cdep-audit-secrets`; silently rotating the cursor key invalidates every active
pagination cursor.

The audit service is exposed only as a ClusterIP on port 3008. Browser traffic
must pass through the existing API Gateway and managed Gateway/ingress route;
do not expose the service, PostgreSQL, Kafka, or the Garage administrative
endpoint publicly.
